# Contributor Zone

Welcome to open-personal-tracking.

You do not need to be a software developer to contribute.

Real-time chat and the weekly community call (13:00-14:00) happen on Discord: https://discord.gg/6CjFPH55Rv

## I want to contribute code

Start with:

- `CONTRIBUTING.md`
- `docs/ARCHITECTURE.md`
- issues labeled `good first issue`

Useful areas include:

- React
- TypeScript
- storage
- providers
- importers
- testing
- Android
- iOS

## I want to improve data

Help identify:

- incorrect metadata
- missing metadata
- duplicates
- incorrect external identifiers
- edition or regional ambiguity

Read:

- `CONTRIBUTING.md`
- `DATA_GOVERNANCE.md`

## I want to design

Contributions can include:

- workflows
- mobile UI
- desktop UI
- design system
- interaction design
- accessibility
- empty/error/offline states

Read:

- `DESIGN_PRINCIPLES.md`
- `ACCESSIBILITY.md`

## I want to test

Quality is everyone's responsibility, not only testers'. Get involved as early as possible, ideally while a feature or fix is still being discussed, not just after it is built.

Useful work includes:

- reproducing bugs
- testing releases
- migration testing
- backup restore testing
- accessibility testing (screen readers, keyboard navigation, locales)
- platform testing
- reviewing pull requests for risk and edge cases before they are merged

You do not need to write automated tests to contribute here. Technical skills make testing feedback sharper, and are welcomed, but critical thinking, attention to detail, and a good bug report are just as valuable.

Read:

- `TESTING.md`

## I want to write documentation

Documentation contributions are first-class contributions.

Look for:

- missing guides
- unclear architecture
- recurring contributor questions
- translation opportunities
- migration notes

## I want to help the community

You can help with:

- issue triage
- answering questions
- weekly calls
- moderation
- contributor onboarding
- maintaining good first issues

Read:

- `COMMUNITY.md`
- `CODE_OF_CONDUCT.md`
- `docs/WEEKLY_CALL.md`

## I have a big idea

Open a Discussion first.

If the idea changes a long-term project contract, use the RFC process.

Read:

- `docs/RFC_PROCESS.md`

## First principle

Whatever you contribute, keep this question in mind:

> Does this help people keep ownership of their personal history?
