# Design Principles

## Branding status

Naming, logo, and visual identity work is in progress. `open-personal-tracking` remains a working name, and announcements about the final name, logo, and visual identity will follow once that work is ready to share.

Until then, contributions should follow the principles below rather than assume a fixed visual identity.

## Product feeling

The interface should feel:

- personal
- calm
- durable
- trustworthy
- visual
- information-rich
- culturally aware
- modern without depending heavily on current design trends

## Primary inspiration

The project may learn from products such as TV tracking applications, media databases, reading trackers, and collection tools.

Useful patterns include:

- strong cover and poster presentation
- fast progress tracking
- dense but understandable metadata
- clear item detail pages
- timeline-based personal history
- collections
- contextual discussions

These references are interaction inspiration, not visual templates to copy.

## Content first

Movies, books, manga, games, albums, and other tracked objects already contain strong visual identities.

The interface should provide structure rather than compete with that content.

A useful principle is:

> The collection provides the color. The application provides the frame.

## Personal history over discovery

The home screen should primarily answer:

- What am I currently doing?
- What did I recently mark?
- What has changed in my personal history?
- What do I want to continue?

Discovery is valuable but should not dominate the application.

## Tracking should be immediate

Common actions should require minimal interaction:

- mark as started
- update progress
- complete
- pause
- drop
- rate
- add a note

## No aggressive gamification

Statistics may help users understand their history.

Avoid turning personal activity into performance pressure.

Do not assume that streaks, rankings, badges, or engagement loops are desirable.

## Network and personal data must look distinct

The UI should clearly separate:

- personal ratings
- community ratings
- private notes
- public comments
- local activity
- network activity

Users should always understand whether information is private, local, shared, or public.

## Offline confidence

Offline behavior should feel normal rather than degraded.

The application may explicitly communicate when data is stored locally and when backups exist.

## Accessibility

Design must account for:

- keyboard navigation
- screen readers
- reduced motion
- touch targets
- sufficient contrast
- scalable text
- non-color-only status communication
