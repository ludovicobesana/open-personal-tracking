# Support

## Bug

Use GitHub Issues.

Before opening an issue:

- search for duplicates
- include reproduction steps
- include platform information
- explicitly mention any risk of data loss

## Feature idea

Use GitHub Discussions for broad or exploratory ideas.

Use Issues for accepted and bounded work.

## Architecture proposal

Use the RFC process.

## Security vulnerability

Follow `SECURITY.md`.

Do not publish exploitable vulnerabilities as ordinary issues.

## Contribution question

Use the public contributor discussion area so answers can help future contributors.

## Weekly call

Blocked issues, RFCs, triage questions, and contributor coordination may be discussed during the weekly community call.

Attendance is optional.
