# Data Governance

## Scope

This document concerns shared catalog metadata and community-maintained public data.

It does not govern private user-owned tracking data.

## Separation of data

Community contributors may eventually improve shared metadata.

They must never be able to alter another user's private:

- progress
- tracking state
- personal rating
- notes
- tags
- collections
- history

## Shared metadata principles

Shared metadata should be:

- verifiable
- attributable where practical
- reversible
- reviewable
- precise about scope
- resistant to accidental destructive edits

## Evidence

Contributors should provide suitable evidence for factual corrections.

Prefer primary or authoritative sources where available.

## Ambiguity

Do not force one canonical value where the real world contains multiple valid values.

Examples:

- regional release dates
- translated titles
- editions
- reprints
- manga serialization vs collected editions

The data model should preserve distinctions when they matter.

## Provenance

Where practical, shared fields should retain provenance.

A maintainer or future contributor should be able to understand where a value came from.

## Merge and split operations

Merging or splitting entities is high risk.

These operations require:

- clear reasoning
- evidence
- review
- reversible history where possible

## Auditability

Community-maintained data should eventually support an edit history.

Private user data must never appear in public edit history.
