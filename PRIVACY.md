# Privacy Principles

## Default

Private by default.

The core application should not require an account and should not transmit personal tracking data unless the user explicitly enables a feature that requires it.

## Local data

Examples of local personal data:

- library
- progress
- ratings
- notes
- tags
- collections
- history
- custom items

These should remain on the user's device by default.

## Network participation

Optional shared features must clearly explain:

- what is sent
- why it is sent
- whether it is public
- whether it is associated with an identity
- how participation can be disabled

## Analytics

Do not introduce product analytics by default merely because they are conventional.

Any telemetry should require explicit justification and documentation.

## Anonymous aggregate contribution

If aggregate contribution exists, collect the minimum information needed.

Do not upload complete local databases for analytics.

## Social features

Public comments, profiles, lists, reactions, and follows belong to a separate network trust boundary.

The existence of a network identity must not change ownership of the local history.

## Deletion

When network accounts exist, document:

- account deletion
- public-content deletion behavior
- retention periods
- backups
- moderation exceptions

## Privacy by architecture

Prefer architectural guarantees over policy promises.

If data does not need to leave the device, do not send it.
